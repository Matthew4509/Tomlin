Audits

The latest built-in audit of each project. Run one from a project's … menu › Scan app, or when you start its local copy. It is a simple check: it catches common core faults, not everything. Prompts

Prompts you use again and again, sorted into categories. Help

The Bridge is the part of TOMLIN that lists the projects on this PC, starts their local copies, checks them for common faults and keeps an eye on their git backups and live sites. It runs inside TOMLIN, on this PC only.

Getting started

It comes with TOMLIN: nothing to install. TOMLIN at the top of the left panel goes back to chats, staff and jobs; TOMLIN's own left panel has Projects to come back here. TOMLIN's app lock covers these pages too.

The first list holds the folders beside TOMLIN's own folder (or, for an installed copy, its workspace). Add the folder that holds your projects on the Folders page, or single projects kept somewhere else. Used Myia Bridge before? About › Bring in from Myia Bridge copies its folders, prompts, private details and lists here.

Projects

Each row shows the tokens your AI tools used on it, when it last changed, and its state, with two buttons and a … menu:

  • Copy prompt gives you a line to paste into the AI you use. … menu › Start with a hire… hands the same line to one of your staff instead: TOMLIN's Send to card opens with it, and nothing goes until you press Send. In an audit, Fix with a hire does the same with its faults, and Review with AI… has Start with a hire beside Copy prompt. A hire answers from the words it is sent: it does not open the project's folder, so for work across a whole project, Copy is still the way to an AI that reads folders (Claude Code, Codex).
  • Run local copy starts the project's own dev server (from its .claude/launch.json or project.json) and opens it. Stop ends it.
  • … menu › Scan app (audit) runs the built-in audit (about 130 rules: keys, including a key removed from the files that the git history still holds, injection, sign-in and payment gaps, uploads, saving and replies, .htaccess, accessibility, and checks that read the project as a whole: limits, clean-up jobs, the privacy page against the code, release builds). It catches common core faults, not everything. It also finds what publishing the project would give away about you; list your own private details under Audits › Private details. A finding names the detail's label, never the detail. Not a fault… beside a finding sets that one place aside with your reason (it comes back if the line is edited); Import report-back… does the same from a pasted "False flags" table. Review with AI… builds a prompt to copy into any AI for the faults no rule finds (money, access, promises); paste its answer into Import report-back… and its findings go on the project's fault list, each open, fixed or not a fault. Old copies of the app inside the project folder (an "original" or "-fixes" copy, an unpacked release beside its zip, older versions side by side) are left out so a fault is counted once, where the app lives; the audit's notes name each one and why. To scan one anyway, list it under auditInclude in the project's project.json.
  • … menu › Hosted live takes the address the project is hosted at: a green, amber or red light shows whether it answers. It is checked when the Bridge starts and then every 5, 10 or 15 minutes (Check every in the Live sites panel, which also shows how long each page took). A site that goes down shows a red message that stays until you close it. The Bridge sends no emails or phone alerts: a site that must not go down unnoticed needs a monitoring service of its own.
  • … menu › Remove from list only takes a project off the list. Its folder and files are never touched. Folders › Removed from the list brings it back.
  • … menu › Last audit, Open folder, Open terminal here, Move to top / up / down / bottom, and Hide from display: a hidden project stays on the list but out of view until Show hidden is on.

The bar above the list has Add project, Scan folders (what is new or gone since the last scan), Refresh, List / Tiles, the sort order (Last updated, My order, Most tokens, Name, Running first; in My order you can also drag a row), Stop all (everything the Bridge started; a tick adds other programs holding your projects' ports, each named first), Show hidden and search.

The window

  • Bridge near the top of the left panel takes you home to Projects. Its light shows ● Connected, or Connection lost in red when TOMLIN stops; then Reconnect appears and the page reconnects by itself once TOMLIN answers again.
  • This PC: CPU, memory, disk and GPU, uptime, and the AI tokens used this month and in total (Recount counts them again).
  • Running: every site that is up. ● started by the Bridge, ◐ another program holds that project's port. Click a name to open it; the square stops it.
  • Live sites: every live address with its light and how long it took to answer, worst first, with Check now and Check every.
  • The bar at the bottom: how many projects, how many running, when the tokens were counted, and the Git count (click it for the projects waiting for a save or push).
  • The Orbital theme (About › Theme) shows your running sites as satellites over the Earth: click one to shoot it down (that stops it), ↗ opens it. The other themes are Windows, Light and Dark.

Folders, Audits and Prompts

  • Folders: your working folders (every folder inside one is a project), projects added one by one, and projects removed from the list (bring one back here). Add working folder opens the Windows folder picker.
  • Audits: the latest audit of each project. Private details… holds the details about you (email, phone, street, full name) the audit looks for in what you would publish. A detail is typed once and never shown again; the audit shows only its label.
  • Prompts: prompts you use again and again, a tile per category. Click a tile for its prompts, then Copy, Start (to one of your staff, in TOMLIN), Edit (which can move it to another category) or Remove. New category and Add prompt sit above the tiles; inside a category, Rename category and Delete category (which deletes its prompts, and says how many first). Words in [brackets] are yours to fill in. Kept on this PC only.

Git marks

Git keeps a saved history of a project, and a copy on GitHub (or another host) is its backup. The Bridge only reads git: it never commits, pushes or changes a folder.

● Backed up
Everything saved is on the backup copy.
▲ unsaved
Files changed since the last save. Commit them, then push.
▲ not pushed
Saved here but not on the backup copy yet. Push.
▲ Only on this PC
No backup copy at all. Make an empty repository on GitHub, then link it and push.
○ No git
No history and no backup. Fine for scratch folders.

Click a mark for the exact commands to copy into a terminal (… menu › Open terminal here). The Git count in the bar at the bottom lists every project waiting for a save or push.

When files have changed, See what changed in the project's git window shows every changed file since the last save, line by line (green new, red gone), so you can read what an AI changed before you commit. It only reads: nothing is saved or undone.

Copies on my other PCs

Besides git, TOMLIN can keep a copy of a project on your other PCs (the ones linked to it that have Enable backups ticked). Tick Copy this project to my other PCs in its git window: from then on it goes with TOMLIN's backup every 10 minutes when something changed, and only what changed crosses your home network. Each PC keeps the older versions too. In a git repository the copy takes what git keeps (saved files and new ones its .gitignore does not leave out); anywhere else, the whole folder except .git and node_modules. A file over 256 MB is left out and named. Back up now sends it straight away; Bring back puts a PC's newest copy in a new folder (TOMLIN's home, restored projects), never over the project.

● On PC
Its newest copy on that PC holds everything in it now.
▲ Changed since copy
It changed after the last copy; the next backup takes the changes.
○ Not copied yet
Ticked, but no copy has been made yet.

A project is safe from losing this PC when everything is pushed (● Backed up, nothing unsaved) or its copy is up to date (● On PC). The Git count's list of projects only on this PC says which of them have a copy on another PC.

Keeping Git itself up to date

Old versions of the Git program had security holes that a single git clone of a bad repository could set off. About › Git shows your version and warns when it is older than the last security fix this Bridge knows about. To update: winget upgrade --id Git.Git -e, or download it from git-scm.com. Ticking Check online for a newer Git lets the Bridge ask GitHub once a day for the newest version; until you tick it, it asks nothing.

What leaves this PC

Nothing about you or your projects goes to the internet. The only requests that leave for it are plain page requests to the live addresses you add under Hosted live, and, only if you tick it, one request a day to GitHub for the newest Git version. A project you tick under Copies on my other PCs goes only to your own linked PCs, over your home network and encrypted. Tokens are counted from the AI transcripts already on this PC; they are read, never changed or sent.

If something goes wrong

  • The page says Connection lost: TOMLIN stopped. Start it again (its desktop icon, or Start TOMLIN.cmd); this page reconnects by itself.
  • A project shows "No start command": add a "start" to the project's own project.json, or list it in projects.json in the Bridge's data folder (TOMLIN's home, dataridge; see README.md).
  • Your folders or prompts are suddenly back to the start: the file that held them could not be read. It was kept in the Bridge's data folder (TOMLIN's home, dataridge) as settings.damaged-…json or prompts.damaged-…json; close TOMLIN, copy back what you need, and start it again.
  • Git error on a project: click the mark; it says why (git not installed, folder owned by another account, or git settings that could run a program).

Where its data is

Its settings, audits, prompts and lists are in TOMLIN's home, in dataridge, and go with TOMLIN's own backups. Uninstalling TOMLIN removes the Bridge with it.
