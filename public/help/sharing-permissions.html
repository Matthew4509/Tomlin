Sharing and cluster permissions

Each tick a node owner can give a linked host, and the host PIN.

What linked PCs may do on a node is ticked on that node, under Settings, This PC, Sharing and cluster permissions (Network, Sharing shows the same). Set on the PC that shares. Each tick asks the app lock PIN; Allow all ticks them all (but not "connect directly", below); all are off until you tick them, except turning the PC off, which is on until you untick it. A linked host is trusted like an administrator, but only for what is switched on. An update is program code sent over the link, so a guest never can.

Models

  • Sharing of models lets them copy the shared models. Visible only to computers connected on your network. If permissions are enabled, anyone with the PIN can push, pull, access or delete these models.
  • Accept models from linked PCs lets them send it models.

Host control

  • Enable backups lets them back their projects up there and keep restore points (Backups). It is a local git that backs up the host's projects to this node.
  • Allow host to update TOMLIN remotely lets a newer TOMLIN be installed there, each time with that PC's app lock PIN typed on the PC sending it (Updates). It makes it easy to update headless nodes. A copy not started by the installed TOMLIN or Start TOMLIN.cmd cannot start a new version by itself: install it with Install TOMLIN.cmd, or start it with Start TOMLIN.cmd.
  • Allow host to test and change model run settings lets them pick the Guessing model of a model there, on that PC's card under Linked PCs (Speed).
  • Allow host to turn this PC off: a linked host may shut this PC down, one PC at a time, with this PC's app lock PIN typed on the host. On unless you turn it off. A guest can never do it.
  • Let PCs my host introduces connect to this PC directly: direct links. Off until you switch it on, and not part of Allow all.
  • Let linked PCs pull TOMLIN updates from here lets someone at a linked PC with an older TOMLIN copy this PC's TOMLIN (its app files only, never your data or models) to update their own (no PIN: nothing changes on the PC it comes from).

Cluster

  • Allow to be used as part of a cluster (it serves both: Cluster, for a model that will not fit on one PC, and Max mode, a chat's Max switch, for a model that does fit, to raise its tokens a second; see Max mode and Cluster) lets one of them at a time run a model too big for it with part of it on that PC's card and RAM, only while nobody is using that PC (Windows locked, or no key press or mouse move for the minutes chosen there; using the PC again ends it at once). It is the only tick a cluster needs: the borrowing PC borrows from every linked PC that allows it, only for a model that does not fit it alone, unless Don't borrow from it is ticked on that PC's tile under Linked PCs.

Sending the NVIDIA runner needs no tick (it must be the very runner TOMLIN names, file for file): any linked PC may, while nobody is using that PC.

The host PIN

The host PIN (Network, Linked PCs, Set the host PIN): one PIN of 6 to 12 digits, or a password of 6 characters or more, typed on this PC for all the linked PCs. Setting it gives it to each linked PC: each asks for its own app lock PIN once, then holds the host PIN for this PC only. From then on Update all linked PCs asks for the host PIN once and updates every PC that holds it; a PC that does not asks for its own PIN, as before. The host PIN also turns a PC off or deletes a model there, and the ticks on that PC are still needed. This PC keeps only a scrambled copy of it. Change the host PIN gives the new one to the PCs that hold the old one without asking their own PINs again; Turn the host PIN off takes it back from every PC that answers.
