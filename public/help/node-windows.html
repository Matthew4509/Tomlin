Windows settings for a node

Hibernation, automatic sign-in, setup reminders, sleep and waking, start with the PC.

A node that runs on its own (no screen, no keyboard) needs three Windows settings, listed on the Network page under (!) Three Windows settings for a node that runs on its own.

The three settings

  1. Turn off hibernation. A hibernating node stops answering. Windows also keeps a hidden file for it about three quarters the size of this PC's RAM. In Command Prompt, run as administrator, type powercfg /h off (powercfg /h /size shows how big the file is).
  2. Sign in automatically. For a node with no screen or keyboard (headless). After a restart Windows waits at the password screen, and TOMLIN does not start until someone signs in. Press Windows + R, type netplwiz, untick Users must enter a user name and password to use this computer, and enter the password once. If that box is missing, turn off Settings › Accounts › Sign-in options › For improved security, only allow Windows Hello sign-in first. Anyone at the PC can then sign in, so use it only for a PC in a safe place.
  3. Stop the "finish setting up your device" and backup reminders. Windows can show a full-screen prompt after an update or start, and TOMLIN does not answer behind it. In Settings › System › Notifications › Additional settings, untick the options about suggesting ways to finish setting up this device and about tips and suggestions. Names differ a little between Windows versions.

Start TOMLIN when this PC starts

On the node, Start TOMLIN when this PC starts (This PC; the same as Start on start up in the My PC window) starts TOMLIN with Windows, and Start it again starts it if it has stopped. It needs TOMLIN started by its installed program or by Start TOMLIN.cmd (see Installing TOMLIN).

Sleep and waking

Sleep and waking. A node stays awake by itself while a linked PC has a model loaded on it or is waiting for an answer, and may go to sleep when it has been idle for a minute or more (it keeps to your Windows power settings then).

When a request comes for a node that is asleep, this PC wakes it with a wake-on-LAN message and waits up to 90 seconds. That works only if wake-on-LAN is switched on in the node's BIOS (often called Wake on LAN or Power On by PCI-E) and in its network card's settings in Windows (Device Manager, the card, Power Management, Allow this device to wake the computer, and Only allow a magic packet).

The node's network address is learned while it is awake, so it must have answered this PC once first. A laptop on Wi-Fi usually cannot be woken; use a cable.

Can other PCs reach this one?

On the node, Check under this question looks at the PC's own settings (its connection, how its address was set, its router, network type and firewall) and changes nothing. It gives the steps, or the lines, that fix each fault, with Copy for one line that runs them: Start menu, type PowerShell (or cmd), right-click, Run as administrator, paste, press Enter, then Check again. The address to type on the main PC is shown under it.
