Max mode and Cluster

Borrow linked PCs to run a model too big for one, or to try to raise speed.

Beside Web, each chat has Max: off. Max mode is built, and not yet run on two PCs: nothing about its speed is measured. It is for a model that fits on this PC alone: it borrows from your linked PCs to try to raise the tokens a second.

Cluster is for a model that will not fit on one PC: it borrows so the model can run at all, by itself, with or without the switch. Press it (Max: on) and it stays on for that chat.

Nothing reloads by itself: when the model is loaded on this PC alone, a card under the next answer says what a Max load needs and about how long it takes (loads over the link took 3 to 16 minutes), with Reload with linked PCs and Not now; it is offered once for each load. The model stays loaded until the Max load can start: when it cannot, the card says why and nothing changes.

The switch is faded, with the reason under the chat box once you press it, when the model does not fit one PC (Cluster runs it), when no linked PC allows it ("Allow to be used as part of a cluster" on that PC), when none is on, or when the PCs run different llama.cpp builds (the PC that blocks is named).

What Max mode uses: only expert parallel, for a mixture-of-experts model (Qwen3-30B-A3B, gpt-oss, Qwen3-Next and the like) on a PC with an NVIDIA card, every PC on the same build. It never uses a layer split itself: a mixture-of-experts model, or one that fits this PC's graphics card, ran slower split than on one PC every time it was measured. Any other model loads as it would with Max off, so the switch never makes a load worse: a dense model too big for this PC's card still gets a card lent by a linked PC, as without the switch.

Expert parallel has beaten the layer split on two PCs, but whether it beats one PC alone for a model that fits has not been measured, so the first Max load of a model on a set of PCs is the measurement: if it was not faster than this PC alone, Max mode is not used for that model again, and the line under the answer says so with both speeds.

Under each answer with linked PCs lending: which PCs lent, the tokens a second, and the last speed measured on this PC alone. The next engine to try, if expert parallel does not beat one PC, is a small guessing model on a linked PC (not built).

The Cluster page

Network, Cluster (Open the cluster page) puts linked PCs together for models too big for this PC and switches them on or off as one: drag nodes into the cluster, choose a model and press Start chat. It also shows what our own clusters measured, on three PCs over a wired 1 Gb network, in tokens a second while writing:

  • A cluster makes a big model possible, not fast: the 89.5 GB Qwen3.8-Flash-Next ran at 1.9 tokens a second, about a sentence every ten seconds.
  • For a model that fits one PC, use that PC. In three tests the single PC was faster twice and about the same once; the network between the PCs costs more than the extra card gives.
  • Three PCs were not better than two: a third, slower PC gave from less than half to about one and a half times the speed of two, and long loads can fail.
  • Against an SSD it is not measured: a model bigger than the RAM is read back from the drive as it is used, and a drive is much slower than RAM. We expect the cluster to be faster whenever the whole model fits in the pool's RAM, but that is an expectation, not a test.

The nodes lend only after their owner ticks Allow to be used as part of a cluster (Sharing and cluster permissions).
