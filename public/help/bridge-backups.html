The Bridge: backups

Zips to a drive, and copies on your other PCs.

Backups to a drive

  • Backups (left panel) › Turn on backups…: choose where they go. A USB drive is best, so a copy survives this PC; another drive or a network folder works too. The zips go in a TOMLIN Backups folder there. A drive is known by its serial number, so a new letter (E: one day, F: the next) does not matter.
  • Tick a project (the box before its name, or Select all), then Run backups. It shows each project's size, how long it should take and the drive's free space before it starts, and will not start when it will not fit. … menu › Back up now… backs up one project.
  • Each project becomes one zip, with a .txt beside it saying what is in it. Every file in the zip is read back and checked before it counts. The git history goes in; folders a project rebuilds by itself (node_modules and the like) are left out unless Full backup is ticked on the Backups page.
  • The mark on each row: ● Zipped (and when), ▲ Changed since zip, ✕ Zip backup failed (click it for why). Other PCs beside it is the other kind of backup: copies on your linked PCs.
  • Backups are only ever added: nothing on the drive is deleted to make room (Keep can keep only the last few, off to start). A full drive keeps its backups: plug in another and add it. To restore: right-click a zip › Extract All.

Copies on my other PCs

Besides git, TOMLIN can keep a copy of a project on your other PCs (the ones linked to it that have Enable backups ticked). Tick Copy this project to my other PCs in its git window: from then on it goes with TOMLIN's backup every 10 minutes when something changed, and only what changed crosses your home network. Each PC keeps the older versions too. In a git repository the copy takes what git keeps (saved files and new ones its .gitignore does not leave out); anywhere else, the whole folder except .git and node_modules. A file over 256 MB is left out and named. Back up now sends it straight away; Bring back puts a PC's newest copy in a new folder (TOMLIN's home, restored projects), never over the project.

● On PC
Its newest copy on that PC holds everything in it now.
▲ Changed since copy
It changed after the last copy; the next backup takes the changes.
○ Not copied yet
Ticked, but no copy has been made yet.

A project is safe from losing this PC when everything is pushed (● Backed up, nothing unsaved) or its copy is up to date (● On PC). The Git count's list of projects only on this PC says which of them have a copy on another PC.
