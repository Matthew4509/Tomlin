Memory

The memory editor: the team's and each hire's notebook, kept as plain .md files.

Memory is what your staff keep between chats: lines you write or pin, read fresh before each answer. Each hire has a notebook of their own, and the team notebook is read by everyone you hire. A hire with the Default role reads no memory. A model never writes memory by itself: it may suggest a line, which waits in the Inbox until you keep it.

Three quick ways to add a line, with no model: type remember: … in a chat (remember for the team: … for the team notebook), press Pin under a message, or press Add entry in the editor.

The memory editor

The editor is a page of its own. Open it from Memory in Settings (under Staff and models), which opens at the team notebook; from Memory on a person's page, at their notebook; or from a chat's Memory window, Open the memory editor, at the notebook that chat reads.

  • On the left: the notebooks, the team's and each hire's, with how many entries each has and how full it is. A notebook holds up to 200 entries or 100,000 characters.
  • In the middle: the notebook you picked, as a List or as Text.
  • On the right: what the model gets of it on the next answer.
  • At the top: Search, Add entry, Add group, List, Text, Open file and Open folder.

List and Text

List shows each entry on its own, in its group, with who wrote it (you, pinned, or suggested by a model) and when. Each has Edit, Move to… another group and Delete (with Undo straight after); drag an entry to put it in another order. An entry can run to several lines, up to 4,000 characters. Add group makes a group, and a group can be renamed, or deleted once it is empty.

A group called Always send is sent on every turn. The other entries are sent whole when they fit; when they do not, the ones that share the most words with what you asked go first.

Text shows the whole file in one box, as Notepad shows it. ## starts a group; each entry is a line starting - , with its other lines indented two spaces, or a block of lines up to a blank line. Save reads it back first and says what it found; a change made in Notepad meanwhile is not written over.

Search

Search looks in every notebook at once as you type, and lists what it found with the notebook and group of each (the first 100). Press one to open its notebook at that entry.

The .md files

Each notebook is a plain Markdown file in TOMLIN's data folder, in data\memory: team.md for the team, and one staff-….md for each hire. A small file beside each keeps who wrote each entry and when. It knows an entry by its words, so changing an entry's words in the file makes it yours: it then shows as written by you, even if a model suggested it first (its group, such as Always send, stays). Open file opens the notebook in Notepad: change it there and save, and TOMLIN reads it again before the next answer (the editor reads it again when you come back to its window). Open folder opens data\memory in Explorer, so any notes app pointed at the folder can read it too. Whatever is written by hand loads as best it can: no line is refused. An entry that looks like a key or a password is kept in the file but marked, and is never sent to a model.

The Inbox

A model may end an answer with a line it suggests for its memory, and an Agent may propose up to 3 lines a run (when its recipe allows it: see Agents). Each waits in that notebook's Inbox group, at the top of the List, and is never sent to a model while it waits. Keep moves it into the notebook, Edit then keep lets you change it first, and Drop throws it away; tick several to keep or drop them together.

What the model gets

The right side says what the hire's model gets of this notebook on the next answer: its model and context size, and the room memory may take (each notebook up to a fifth of the model's room). For each part, the notebook itself, the team memory and Always send, it says whether it is sent whole, in part, or left out for want of room. With nobody hired yet, it says the team notebook is read by everyone you hire. In a chat, the Memory window's What they read for the next answer shows the same for that chat: the instructions, the memory lines and the chat so far.
